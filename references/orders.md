# 本人订单查询

## 范围与浏览

从请求提取日期范围、商品关键词、店铺、规格及所需字段。相对日期使用用户时区，近三个月按日历月份回推并注明边界。缺非关键条件时先查最近可见列表；缺少会实质改变答案的条件才提问。

1. 检查浏览器标签页，复用官方淘宝/天猫会话，进入“已买到的宝贝”或等价入口，不硬编码未经验证的深层地址。
2. 读取当前页面结构，以当前元素引用或可访问名称操作；导航、翻页或弹窗后重新定位。
3. 优先用订单搜索、日期和状态筛选，列表摘要不足时只查看匹配候选详情和物流。
4. 多笔同名订单用日期、店铺、规格区分。仍无法确定目标时提供必要差异供用户选择。
5. 用户要求完整区间时逐页核对，记录已看范围及重复项，直到越过下界或无下一页。验证中断或页面限制时报告实际覆盖范围，不声称完整，不高频刷新。

## 字段与口径

按需返回下单日期、商品、SKU、数量、店铺、交易状态、订单实付、币种、退款状态、最新物流节点及发票状态。字段未显示则注明，不推断。

- 订单实付与单品标价分开；多商品合单不能把整单实付重复计入每件商品。
- 运费、优惠、退款按页面可见口径记录；退款申请中不等于到账。没有依据不平均分摊金额。
- 多包裹分别记录状态，一个包裹签收不等于整单签收。
- 内部去重可用完整订单号，回复默认末四位加日期和店铺；明确要求导出完整标识时遵从需求。
- 状态保留页面原文，物流时间与查询时间分开。发票状态仅在页面显示时记录。

## 结果核验

紧凑表格呈现所需字段，注明日期区间、筛选条件及已覆盖范围。仅使用页面实际提供且适合分享的订单链接，不构造含 Token 地址。合计标明订单实付或扣除已到账退款后的净额，不跨币种直接相加。

核对匹配条件、合单去重及缺失值；不能把未知金额记为零。只查看当前列表时明确说明，不能宣称已查全部。

真实账号验收应覆盖同名多笔、多商品合单、部分退款、多包裹、登录过期和分页中断。未经过实际页面验证前，只能报告流程已定义，不能宣称端到端测试成功。
